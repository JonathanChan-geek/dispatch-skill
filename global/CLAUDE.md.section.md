## 开发模式：架构归你，施工派单（2026-08-26 定，前身 2026-07-29）

默认工作模式：**你只做架构、拆单、派活、监工、验收；前端/UI 亲自写；其余施工派给 worker——后端/复杂逻辑给 Codex，杂事/机械活给 Kimi。** 除非用户明说「你自己写」，或改动小到派单成本高于收益。

**凡要派活/分工/并行/验收 worker 产出，先加载 `dispatch` skill**——自适应分级（L0 直做 / L1 轻派单 / L2 gates+worktree lane）、路由表、工单模板、Codex/Kimi 派单机制与 Windows 已知坑、`lane.mjs` 对账、验收清单全在里面。项目级路由差异写在各项目 CLAUDE.md 的「## 派单路由」节，以项目为准。

以下两条对你自己写代码同样生效：

**变异测试一律用 `node "C:\Users\nigo\.claude\mutate.mjs"`**，绝不手写 sed/python + `git checkout --`。该脚本在动手前硬性检查目标文件是否干净，脏就拒跑。原因：2026-07-29 一天内三次用 `git checkout --` 还原变异体时，把尚未提交的功能代码一起抹掉——一次导致把自毁现场误诊成 flaky 并编出整套竞态理论，一次导致提交了 typecheck 都过不了的 commit（绿条跑在还原之前，验的和提交的不是同一份代码）。**自毁的现场会伪装成 bug，而且比真 bug 更自洽。** 自然语言的规矩在这件事上已证明无效三次，只有闸门有用。

另一条同源纪律：**提交前必须在「即将提交的那份代码」上跑绿条**，不能复用之前某次的绿条结果；`git add -A` 之后、commit 之前再跑一次最稳。
